# F1 — Primitives: button, toggle, toggle-group, separator, avatar

Source: base-ui `types.md` autogenerated references + source review
(2026-06-13). Every prop/behavior captured; React-isms (`className`-as-
function, `style`-as-function, `render`, `inputRef`) are NOT listed per
component — our equivalents are universal: static `class`/attrs in the
template, state styling via the data-attribute contract, composition via
slot structs (feature 00).

---

## button

Base-ui surface: single part, renders `<button>`.

| base-ui prop | ours | static/signal |
|--------------|------|---------------|
| `disabled: bool = false` | `config.disabled` | static (dynamic ⇒ caller passes a getter and we add the effect) |
| `focusableWhenDisabled: bool = false` | `config.focusable_when_disabled` | static — renders `aria-disabled="true"` WITHOUT the `disabled` attr so the button stays in tab order; click/keys suppressed |
| `nativeButton: bool = true` | always native `<button type="button">` | — (the non-button escape hatch is React `render` polymorphism; ours: write your own element) |

Behavior captured:
- Native `<button>` gives Enter/Space activation, focusability, form
  semantics for free — NO JS keyboard code.
- `focusableWhenDisabled` is the one subtle behavior: disabled-but-focusable
  for tooltip/AT discoverability; suppresses activation while announcing
  disabled state.
- Old-draft addition kept: optional `loading` signal → `aria-busy`,
  `data-loading` (base-ui has no loading state; ours is additive).

Data attributes: `data-disabled` (+ ours: `data-loading`).

**Platform notes (the new-CSS angle):**
- The HTML **Invoker Commands API** (`commandfor` + `command` attributes)
  lets a plain button open/close dialogs and popovers with ZERO JS. Our
  trigger-flavored buttons (dialog/popover/menu triggers in F4/F5) should
  emit `commandfor`/`popovertarget` attributes when targeting native-layer
  components — server-rendered HTML then works before/without wasm. Adopt
  as a progressive default, with the JS dismiss manager as the fallback
  wiring.

## toggle

A two-state button. Renders `<button aria-pressed>`.

| base-ui prop | ours | static/signal |
|--------------|------|---------------|
| `pressed` / `defaultPressed` / `onPressedChange` | ONE `(pressed, set_pressed)` signal pair | signal (the controlled/uncontrolled/callback triple collapses) |
| `value: string` | `config.value` | static — identifies the toggle inside a toggle-group |
| `disabled = false` | `config.disabled` | static |

Behavior: click/Enter/Space flips `pressed`; `aria-pressed="true|false"`.
Data attributes: `data-pressed`, `data-disabled`.

Event details: base-ui hands every change callback a
`ChangeEventDetails { reason, event, cancel(), allowPropagation(), trigger }`.
Ours: callbacks receive `EventData` (F08) — already carries the trigger
element id + native event facts; `cancel()` maps to NOT writing the signal
(the handler owns the write — cancellation is just not calling the setter).
This mapping applies to EVERY component below; not repeated.

**Platform notes:** none needed — native button + one attribute.

## toggle-group

Shares pressed state across toggles; renders `<div role="group">`.

| base-ui prop | ours | static/signal |
|--------------|------|---------------|
| `value: string[]` (+default/onChange) | `(values, set_values)` signal pair (`Vec<String>`) | signal |
| `multiple: bool = false` | `config.multiple` | static — single mode unpresses the others on press |
| `loopFocus: bool = true` | `config.loop_focus` | static (M5 parameter) |
| `orientation = horizontal` | `config.orientation` | static |
| `disabled = false` | `config.disabled` | static |

Behavior:
- M5 composite: Arrow keys move focus between toggles (orientation-aware;
  loop per `loopFocus`); pressed state changes only on activation.
- Single mode = radio-like exclusivity but allows none-pressed.
- Child toggles register by their static `value`; group writes the Vec
  signal; each toggle's `data-pressed` is a tiny computed off the Vec.

Data attributes: `data-orientation`, `data-disabled`, `data-multiple`.

## separator

Pure markup. `<div role="separator" aria-orientation data-orientation>`.
All static; a PURE component (works without ctx/receiver — first proof that
the catalog supports no-runtime components).

**Platform notes:** `<hr>` exists but is horizontal-styled by UA; keeping
the `div role="separator"` form matches base-ui and styles cleanly.

## avatar

Parts: Root (`<span>`), Image (`<img>`), Fallback (`<span>`).

| base-ui surface | ours |
|------------------|------|
| `Root.State.imageLoadingStatus: 'idle'\|'loading'\|'loaded'\|'error'` | internal `loading_status` signal |
| `Image.onLoadingStatusChange` | optional callback config |
| Fallback `delay: number` | static config — only show fallback after N ms (avoids flash) |

Behavior captured:
- Image wires `load`/`error` events (F08) → status signal; Fallback is
  visible only when status ≠ loaded (`data-hidden` toggling — visibility,
  not structure; no `<Show>` needed).
- Image data attributes `data-starting-style` / `data-ending-style` while
  animating in/out — the M7 transition convention's first appearance:
  attribute present during the entry/exit frame so CSS can transition.

**Platform notes:** `@starting-style` CSS (Baseline 2024) does natively
what `data-starting-style` polyfills — entry transitions without JS. M7
SHOULD emit the data-attributes AND document the pure-CSS
`@starting-style` path; where no exit animation is needed, zero JS.

## Slots/parts summary (feature-00 shapes)

```rust
pub fn button(cfg: ButtonConfig, slots: ButtonSlots /* children */) -> Html;          // pure-capable
pub fn toggle(ctx, rcv, cfg: ToggleConfig, pressed, set_pressed, children) -> Html;
pub fn toggle_group(ctx, rcv, cfg: GroupConfig, values, set_values, children: Vec<Slot>) -> Html;
pub fn separator(cfg: SeparatorConfig) -> Html;                                       // PURE
pub fn avatar(ctx, rcv, cfg: AvatarConfig, slots: AvatarSlots { fallback }) -> Html;
```

Machinery: M5 (toggle-group), M7 (avatar). Acceptance tests per component:
ARIA attrs on the op stream, data-attribute transitions on state change,
keyboard contract (group arrows), pure-form parity (`to_markup`).
