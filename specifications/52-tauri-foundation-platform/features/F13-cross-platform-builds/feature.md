# F13 — Cross-platform builds: Desktop, Android, iOS

## Overview

`foundation_platform` must compile and run on all three Tauri v2 targets:
Linux/macOS desktop, Android, and iOS. This feature makes PlatformBuilder
runtime-agnostic, creates example apps for each target, and adds Docker-based
CI test environments.

[Decision 04](../decisions/04-deployment-surfaces.md) defines deployment
surfaces including native static libraries for mobile. Tauri v2 provides
the host layer on all three platforms — we wrap it, we don't replace it.
[Decision 14](../decisions/14-docker-test-environments.md) defines the
Docker-based test environments.

## Dependencies

Depends on:
- `F12-mvp-integration` — Demo app on desktop must work first

## Requirements

### 1. Runtime-agnostic `PlatformBuilder`

`PlatformBuilder` must be generic over `R: Runtime`, not hardcoded to
`tauri_runtime_wry::Wry<EventLoopMessage>`. Tauri v2 uses Wry on all
platforms, but the binary type differs — a desktop binary links Wry
directly; an Android `.so` links it via JNI. Using `R: Runtime` handles
all cases through Tauri's existing abstraction.

### 2. Example app per platform

Three example crates prove each target works. All use the same `platform_run!`
macro with identical user code — different compilation targets only.

```
examples/
├── platform_desktop/     # Desktop: cargo tauri dev
│   ├── Cargo.toml, build.rs, tauri.conf.json
│   ├── public/index.html
│   └── src/main.rs       # platform_run!(PlatformBuilder::new()...)
│
├── platform_android/     # Android: cargo tauri android build
│   ├── Cargo.toml, build.rs, tauri.conf.json
│   ├── public/index.html
│   ├── src/main.rs       # platform_run!(PlatformBuilder::new()...)
│   └── src-tauri/        # Generated by cargo tauri init
│       ├── Cargo.toml    # depends on foundation_platform
│       └── src/lib.rs    # #[tauri::mobile_entry_point]
│
└── platform_ios/         # iOS: cargo tauri ios build
    ├── Cargo.toml, build.rs, tauri.conf.json
    ├── public/index.html
    ├── src/main.rs
    └── src-tauri/        # Generated by cargo tauri init
```

### 3. Desktop example

```rust
use foundation_platform::*;

fn main() {
    platform_run!(PlatformBuilder::new()
        .route("/app/*", webview_app().with_profile(Profile::App))
        .route("/remote/*", remote_fetch()
            .with_profile(Profile::TrustedRemote)
            .with_cache_policy(CachePolicy::NetworkFirst))
        .route("/cached/*", remote_fetch()
            .with_cache_policy(CachePolicy::CacheFirst))
        .setup(|session| {
            println!("Desktop — session {:?}", session.session_id());
        }));
}
```

**Verify:** `cargo tauri dev` → window opens with Foundation Platform title.

### 4. Android example

Same `platform_run!` code. `cargo tauri android init` generates the Gradle
project. `cargo tauri android build` compiles `foundation_platform` to a
native `.so` via NDK and packages the APK.

**What proves it works:**
- `cargo tauri android build` produces a signed APK
- `adb install` deploys to emulator/device
- App launches → WebView shows foundation_platform dashboard
- Logcat shows `Session: SessionId(...)`

### 5. iOS example

Same code. `cargo tauri ios init` → Xcode project. `cargo tauri ios build` →
`.ipa`. (Requires macOS + Xcode.)

### 6. Runtime-agnostic code checklist

No file in `foundation_platform/src/` may hardcode `tauri_runtime_wry`.
Use `R: Runtime` generic or avoid Tauri types entirely.

| File | Tauri dependency | Status |
|---|---|---|
| `builder.rs` | Wraps `tauri::Builder<R>` | Must be generic ✅ |
| `ewe.rs` | `register_ewe_protocol<R: Runtime>` | Already generic ✅ |
| `session.rs` | None | Runtime-free ✅ |
| all others | None | Runtime-free ✅ |

### 7. Docker CI environments

Docker images in `artefacts/dockerfiles/{linux,android,windows}/` provide CI
test runners with platform toolchains and VNC for visual debugging.

## Verification

```bash
# Desktop
cd examples/platform_desktop && cargo tauri dev

# Android
cd examples/platform_android
cargo tauri android init
cargo tauri android build

# iOS (macOS only)  
cd examples/platform_ios
cargo tauri ios init
cargo tauri ios build

# Unit tests (all platforms)
cargo test --package foundation_platform
```
