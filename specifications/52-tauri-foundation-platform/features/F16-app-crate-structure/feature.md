# F16 — App crate structure & project convention

## Overview

Every foundation_platform project follows ONE standard layout. The physical
split between native code (`src-tauri/`) and WASM code (`app/`) is a
consequence of Rust's single-target-per-crate model — not a design choice.

`src-tauri/` compiles to native (aarch64, x86_64, etc.). `app/` compiles to
wasm32. They CANNOT share a Cargo.toml. The root `build.rs` bridges them.

## Why this exists

Users should NEVER think about compilation targets. They write `#[wasm_bin]`
functions in `app/src/lib.rs`, write `#[platform_bin]` in `src-tauri/src/lib.rs`,
and `cargo build` does everything. The project template enforces this.

## Requirements

### R1 — Standard project layout ✅ (platform_android exists)

```
my-platform-app/
├── build.rs               ← root: discovers wasm entrypoints, compiles app/
├── Cargo.toml             ← [workspace], thin lib, no deps
├── src/lib.rs             ← empty placeholder (so cargo has a crate root)
├── src-tauri/              ← native .so / binary
│   ├── build.rs            ← foundation_platform::codegen::generate_platform_code()
│   ├── Cargo.toml          ← crate-type=["lib","cdylib","staticlib"], [workspace]
│   ├── tauri.conf.json
│   ├── public/             ← GENERATED by root build.rs (never hand-edited)
│   └── src/
│       ├── lib.rs          ← #[mobile_entry_point] + platform_run!
│       └── main.rs         ← desktop entrypoint → lib::run()
├── app/                    ← WASM UI crate (wasm32 target)
│   ├── Cargo.toml          ← [workspace], cdylib
│   └── src/
│       └── lib.rs          ← #[wasm_bin] / #[wasm_worker] / #[wasm_service]
├── icons/                  ← icons/generated/schemas (auto-generated)
├── assets/                 ← static assets (images, fonts, config)
└── README.md
```

### R2 — Root package is a thin shell 🔄

- [x] `Cargo.toml`: `[workspace]` opt-out, no dependencies
- [x] `src/lib.rs`: empty placeholder
- [x] `build.rs`: orchestrates wasm compilation + artifact generation
- [ ] **Verify**: `cargo build` from root triggers full pipeline

### R3 — `app/` crate: WASM only

- [ ] `[workspace]` — opts out of parent workspace
- [ ] `crate-type = ["cdylib"]` — single `.wasm` output
- [ ] Dependencies: `foundation_wasm` (feature `web`), `foundation_wasm_ui`, `foundation_ui_traits`, `foundation_macros`
- [ ] Contains ALL `#[wasm_bin]`, `#[wasm_worker]`, `#[wasm_service]` functions
- [ ] One crate = one `.wasm` binary (all exports in it — wasm-bindgen style)
- [ ] Proc macros (`#[wasm_bin]`, etc.) validate at compile time

### R4 — `src-tauri/` crate: native only

- [ ] `[workspace]` — standard Tauri v2 mobile convention
- [ ] `crate-type = ["lib", "cdylib", "staticlib"]`
- [ ] `build.rs` calls `foundation_platform::codegen::generate_platform_code()`
- [ ] `tauri.conf.json` has correct identifier + bundle config
- [ ] `src/lib.rs`: `#[mobile_entry_point]` + `platform_run!` + route registration
- [ ] `src/main.rs`: desktop entrypoint → calls `lib::run()`

### R5 — Generated `public/` contents (never hand-edited)

Root `build.rs` produces every file in `src-tauri/public/`:
- [ ] `platform_android_wasm.wasm` — compiled from `app/` (one binary, all exports)
- [ ] `platform_dashboard.js` — `#[wasm_bin]` wrapper (imports runtimes, inits wasm)
- [ ] `bg_worker.js` — `#[wasm_worker]` wrapper
- [ ] `platform_sw.js` — `#[wasm_service]` wrapper
- [ ] `foundation-wasm.js` — core WASM ABI runtime (copied from `foundation_wasm/runtime/`)
- [ ] `foundation-wasm-ui.js` — DOM applicator runtime (copied from `foundation_wasm_ui/runtimes/`)
- [ ] `platform-scheme-interceptor.js` — Android custom scheme polyfill
- [ ] `index.html` — minimal bootstrap page (imports wasm modules, calls init)

### R6 — No hand-written index.html or JS 🔄

- [ ] `index.html` is generated by root `build.rs` from discovered entrypoints
- [ ] Each `#[wasm_bin]` gets a `<script type=module>` import + auto-init block
- [ ] Users NEVER write `public/index.html`
- [ ] If users want custom layout: provide a template, pipeline injects script tags

### R7 — Annotation placement rules

| Annotation | Crate | Why |
|---|---|---|
| `#[wasm_bin]` | `app/src/lib.rs` | Compiles to wasm32 — must be in wasm crate |
| `#[wasm_worker]` | `app/src/lib.rs` | Compiles to wasm32 — web worker |
| `#[wasm_service]` | `app/src/lib.rs` | Compiles to wasm32 — service worker |
| `#[platform_bin]` | `src-tauri/src/lib.rs` | Compiles natively — boots session + routes |
| `#[platform_worker]` | `src-tauri/src/` | Compiles natively — background thread |
| `#[platform_service]` | `src-tauri/src/` | Compiles natively — in-process server |
| `#[wasm_app]` | Separate wasip1 crate (post-MVP) | wasmtime runtime in shell |

## Verification

```bash
# Root build pipeline:
cargo build                                              # triggers root build.rs
ls src-tauri/public/*.wasm                               # one .wasm file
ls src-tauri/public/*.js                                 # JS wrappers + runtimes
ls src-tauri/public/index.html                           # generated HTML

# WASM app compilation:
cargo build --manifest-path app/Cargo.toml --target wasm32-unknown-unknown --profile uat

# Python/JS/CLI: verify no hand-edited public/ files exist
find src-tauri/public/ -name "*.html" -not -newer build.rs  # all are generated

# Android build:
# cd inside src-tauri/ →
cargo tauri android build  # bundles generated public/ into APK
```
