Scope lock (per direction 2026-06-13): **Chromium only, CDP only.** Firefox /
WebDriver BiDi is a SEPARATE later feature behind the same `WireProtocol` seam.
WebKit is out. Implement only the surface the catalog tests need; grow on demand.
Build (b) the driver first, then (c) the `#[wasm_ui_server]` macro + `TestServer`.

Both browsers are present on this box (`/bin/chromium`, `/bin/firefox`), so a live
smoke test is possible from the start.

## 0. The non-negotiable: deterministic setup AND teardown

The macro owns the lifecycle. Every external resource (server thread, browser
process, temp profile dir, CDP socket + reader thread) is wrapped in an RAII guard
whose `Drop` releases it. Teardown MUST run when the test scope ends **whether the
body returns `Ok`, returns `Err`, or panics**, and must surface the original
outcome upward.

Mechanism:
1. Each resource is a guard with `impl Drop` (idempotent, never panics in Drop —
   log-and-continue). Guards are created in dependency order so reverse-drop tears
   down correctly: **server → browser process → CDP session** created; dropped
   **session → process → server**.
2. The body runs inside `std::panic::catch_unwind(AssertUnwindSafe(...))`. This is
   NOT how teardown happens (Drop already runs during unwind) — it's so we can:
   (a) capture diagnostics (screenshot + console log to
   `target/primal-test/<test>/`) while the page is still alive, and
   (b) translate a panic into a clean, attributed failure.
3. Order at scope end:
   - `Ok(Ok(()))` → pass; guards drop → teardown.
   - `Ok(Err(e))` → `harness.capture_failure("error")`; guards drop; return `Err`.
   - `Err(panic)` → `harness.capture_failure("panic")`; `drop(harness)` explicitly
     (so teardown completes deterministically); `std::panic::resume_unwind(panic)`.
4. Guards are `panic = "log"`-safe: a Drop that itself fails (e.g. process already
   dead) logs via `tracing::warn!` and continues — never double-panics.

```rust
// expansion sketch (generated by #[wasm_ui_server])
fn dialog_test() {
    let harness = ::foundation_browser::test::Harness::setup(CONFIG)
        .expect("wasm_ui_server: setup failed");          // server+browser+session up
    let outcome = ::std::panic::catch_unwind(::std::panic::AssertUnwindSafe(|| {
        __body(&harness.server, &harness.page)             // user code → Result<(), E>
    }));
    match outcome {
        Ok(Ok(())) => { /* drop(harness) → teardown */ }
        Ok(Err(e)) => { harness.capture_failure("error"); drop(harness);
                        panic!("wasm_ui_server: test returned Err: {e:?}"); }
        Err(p)     => { harness.capture_failure("panic");  drop(harness);
                        ::std::panic::resume_unwind(p); }
    }
}
```

`Harness` owns `ServerHandle`, `BrowserProcess`, `CdpSession`, `Page` in a field
order chosen so Rust's declaration-order field drop = correct teardown order.

## 2. The JSON-RPC engine (`jsonrpc/`)

CDP frames: request `{"id":N,"method":"Domain.cmd","params":{…},"sessionId":"…"}`;
response `{"id":N,"result":{…}}` or `{"id":N,"error":{"code","message"}}`; event
`{"method":"Domain.evt","params":{…},"sessionId":"…"}`.

```rust
pub trait WireProtocol: Send + Sync {
    fn call(&self, method: &str, params: Value, session: Option<&str>) -> Result<Value>;
    fn subscribe(&self, method: &str) -> EventSub;        // crossbeam/mpsc receiver of Value
}

pub struct RpcEngine {
    delivery: MessageDelivery,                            // send side (clone of connect())
    next_id: AtomicU64,
    pending: Arc<Mutex<HashMap<u64, SyncSender<Result<Value>>>>>,
    subs: Arc<Mutex<HashMap<String, Vec<Sender<Value>>>>>,// method → listeners
    _reader: JoinHandle<()>,                              // drains client.messages()
    call_timeout: Duration,
}
```

- `connect(ws_url)`: `WebSocketClient::connect(SystemDnsResolver, ws_url, read_to,
  sleep_to)` → `(client, delivery)`. Spawn a reader thread that loops
  `for ev in client.messages()`; on `WebSocketMessage::Text(json)`: parse; if `id`
  present → pop `pending[id]` and send the result/error; else → fan `params` to
  `subs[method]`. The thread owns `client`; exits when the socket closes.
- `call(method, params, session)`: `id = next_id++`; make a `sync_channel(1)`;
  insert sender into `pending`; `delivery.send(Text(frame))`; block on the receiver
  with `call_timeout` → `Result<Value>`. On timeout, remove the pending + error.
- `subscribe(method)`: register a channel; return its receiver. Used for
  `Page.loadEventFired`, `Runtime.consoleAPICalled`, `Runtime.exceptionThrown`.

Sync, no async. One reader thread per connection. This is the ONLY new low-level
code; everything below is JSON shaping.

## 3. CDP client + the minimal command set (`cdp/`)

`CdpClient` wraps `RpcEngine` and exposes ONLY what phase-1 needs. Sessions:
attach to the page target → get a `sessionId`, pass it on every call.

Launch & attach sequence:
1. `Target.getTargets` → find the `type:"page"` target, or `Target.createTarget
   {url:"about:blank"}`.
2. `Target.attachToTarget {targetId, flatten:true}` → `sessionId`.
3. On the session: `Page.enable`, `Runtime.enable`, `DOM.enable`, `CSS.enable`.

Command set (phase 1 — exactly these):

| Capability | CDP calls |
|------------|-----------|
| navigate | `Page.navigate {url}` + await `Page.loadEventFired` (subscribe) |
| evaluate (escape hatch) | `Runtime.evaluate {expression, returnByValue:true, awaitPromise:true}` |
| resolve element | `Runtime.evaluate` returning the node via `DOM.requestNode`, OR `DOM.getDocument` + `DOM.querySelector {nodeId, selector}` |
| box model / geometry | `DOM.getBoxModel {nodeId}` → content quad → `Rect` |
| text | `Runtime.evaluate` `el.textContent` (returnByValue) |
| attribute | `DOM.getAttributes {nodeId}` |
| computed style | `CSS.getComputedStyleForNode {nodeId}` → find prop |
| click / hover | `DOM.getBoxModel` centre → `Input.dispatchMouseEvent` (mousePressed/Released; trusted) |
| type / press | `DOM.focus {nodeId}` → `Input.insertText {text}` / `Input.dispatchKeyEvent` |
| screenshot | `Page.captureScreenshot {format:"png"}` → base64 → file; full-page via `Page.getLayoutMetrics` + clip |
| console / errors | subscribe `Runtime.consoleAPICalled`, `Runtime.exceptionThrown` (drained into the capture buffer) |
| wait for selector | poll `DOM.querySelector` (or `Runtime.evaluate` predicate) with backoff + deadline |

Everything else (network, coverage, emulation, PDF, tracing) is explicitly NOT in
phase 1.

## 4. Browser supervision (`supervisor.rs`)

```rust
pub struct BrowserProcess { child: Child, _profile: TempDir, ws_url: String }
```

- Resolve binary: `$PRIMAL_TEST_CHROMIUM_BIN` → `chromium` / `google-chrome` /
  `chromium-browser` on PATH. Missing → `BrowserError::BrowserNotInstalled`
  naming `mise run test:browsers`.
- Launch flags (subset of Playwright's `chromiumSwitches`, hermetic):
  `--headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage
   --no-first-run --no-default-browser-check --user-data-dir=<temp>
   --remote-debugging-port=0 --remote-allow-origins=*`.
- Endpoint discovery: parse the `DevToolsActivePort` file written into the
  user-data-dir (`<port>\n<wsPath>`), or poll `http://127.0.0.1:<port>/json/version`
  for `webSocketDebuggerUrl`, with a deadline + clear timeout error.
- `Drop`: `child.kill()` + `wait()` (reap), drop `TempDir` (rm profile). Idempotent;
  warns, never panics. (On Unix we kill the process; a process-group kill upgrade
  can come if orphaned helpers appear.)

## 5. Public driver API (phase-1 subset, `browser.rs` + `locator.rs`)

```rust
let driver = BrowserDriver::launch(LaunchConfig::chromium().headless(true))?;
let page = driver.new_page()?;                  // attaches a session
page.goto("http://127.0.0.1:8080/")?;
let dialog = page.locator("dialog");
dialog.expect().to_be_visible()?;               // box model non-empty + computed display≠none
page.locator("[data-dialog-close]").click()?;   // trusted CDP input
dialog.expect().to_be_hidden()?;
page.screenshot("target/primal-test/x.png")?;
```

`LocatorAssertions` (phase 1): `to_be_visible`, `to_be_hidden`, `to_have_text`,
`to_have_attribute`, `to_have_computed_style`, `to_have_count` — each returns
`Result<()>` (so the test propagates) and carries an actionable message
(selector + expected/actual). A retry loop (deadline) absorbs reactive timing.

## 6. `#[wasm_ui_server]` macro + `TestServer` (phase c)

Macro forms: `#[wasm_ui_server]`, `(port=N)`, `("bind", port, https)`,
`(browser="chromium", headless=false)`. Expansion = the §0 sketch.

`TestServer` (in `foundation_browser::test::server`, backed by `foundation_http`):
- builds an App serving: app shell + wasm bundle (from `foundation_wasm_testbed`
  build output), the SSE/WS DOM-op stream, the optional injected `primal-test`
  helper, `/__test__/health`.
- `bind(addr)` (port 0 ok), `Server::serve_with_listener(listener, &shutdown)` on a
  thread; read back the bound `SocketAddr` for `server.url()`.
- `mount(component_fn)`: registers what the page renders (the component under test).
- `push(stream)`: the handle the user pushes UI streams through (channel A).
- `ServerHandle` Drop: `shutdown.signal()`, `thread.join()`.

`Harness::setup(config)`:
1. `TestServer::start(config)` → `ServerHandle` (+ url).
2. `BrowserDriver::launch(config.browser)` → `BrowserProcess` + `CdpSession`.
3. `driver.new_page()` + `page.goto(server.url())`.
4. return `Harness { server, process, session, page }` (drop order = teardown order).
`capture_failure(kind)`: `page.screenshot(...)` + dump console buffer to
`target/primal-test/<test>/<kind>.{png,log}` (best-effort; never panics).
