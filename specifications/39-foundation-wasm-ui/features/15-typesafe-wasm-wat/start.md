# Start: Feature 15 — Type-safe WASM/WAT manipulation (wasmbin port)

## Why

Decision 031 says we own our WASM infrastructure. For *modifying* wasm binaries we currently
lean on `walrus` (general IR) in the testbed. `wasmbin`
(https://github.com/RReverser/wasmbin, Apache-2.0, by Ingvar Stepanyan) offers a more refined,
**type-safe** model: the WebAssembly binary format described 1:1 by Rust types, with
parse/serialize/visit autogenerated from those types, and a `Lazy<T>` wrapper enabling
**zero-cost, minimal-diff editing** (skip unchanged parts on decode, re-encode only what changed).

This feature explores and brings those capabilities into our owned codegen stack, and adds a CLI
binary for wasm/wat manipulation — with **full attribution** to the original project.

## Workflow

1. Read `features.md` — port plan, WAT extension, and the (mandatory) attribution requirements.
2. Read decision 031 (ownership; walrus + wasmbin are both owned wasm-format tooling).
3. Study the source: `/home/darkvoid/Boxxed/@formulas/src.rust/src.wasm/src.tsgen/wasmbin/`
   (`src/{module,sections,types,instructions,indices,builtins,visit,io}.rs`, `derive/`), its
   `LICENSE` (Apache-2.0), `README.md`, and the `Lazy<T>` design.
4. Port the library into `foundation_codegen`, the derive macros into `foundation_macros`
   (per [[feedback_macros_location]]), and the binary into `foundation_codegentools`.
