# Feature 15: Type-safe WASM/WAT manipulation (wasmbin port)

**Library target:** `foundation_codegen` (new `wasm` module)
**Derive macros:** `foundation_macros` (NOT a companion crate — [[feedback_macros_location]])
**Binary target:** `foundation_codegentools` (new `wasm`/`wat` CLI alongside `wasm_bins`)
**Upstream:** [`wasmbin`](https://github.com/RReverser/wasmbin) v0.9.2, Apache-2.0, © Ingvar Stepanyan
**Decisions:** 031 (owned WASM infrastructure)

---

## Goal

Bring `wasmbin`'s type-safe WebAssembly parse/serialize/edit capabilities into our owned codegen
stack, extend them to cover **WAT** (text) as well as binary, and expose a CLI for refined,
type-safe modification of `.wasm` and `.wat` files — all under the existing Apache-2.0 workspace,
with proper attribution.

---

## What wasmbin gives us

- **1:1 typed model** of the wasm binary format (`Module` → sections → types → instructions →
  indices → builtins). Any sub-type can parse/serialize independently.
- **Autogenerated codec/visit** via custom derive (`wasmbin-derive`, synstructure-based) — adding a
  wasm feature = adding Rust types, no hand-written parsing.
- **`Lazy<T>`** — zero-cost editing: decode skips skippable contents (e.g. function bodies) keeping
  raw bytes; encode re-emits only modified parts and copies untouched parts verbatim. Ideal for our
  use cases (inject/rewrite sections without rewriting the whole module).
- **Proposals** behind features: `extended-name-section`, `threads`, `custom-page-sizes`.

### Why this over walrus (decision 031)

`walrus` is a general mutable IR (great for heavy rewrites and for parsing wasm-bindgen output at
the F14 boundary). `wasmbin` is type-safe and minimal-diff — preferred where we want precise,
auditable, low-overhead edits owned by us. Both are wasm-format tools (neither is wasm-bindgen);
they coexist — pick per task.

---

## What we bring over, and where

| Piece | Destination | Notes |
|---|---|---|
| Core model (`module`, `sections`, `types`, `instructions`, `indices`, `builtins`, `visit`, `io`, `Lazy<T>`) | `foundation_codegen::wasm` (new module) | Ported/adapted, not just depended on — owned per decision 031 |
| Derive macros (`wasmbin-derive`) | `foundation_macros` | synstructure-based; **must** live in foundation_macros, never a companion `*_macros` crate |
| CLI binary (inspect / edit / convert wasm & wat) | `foundation_codegentools` | Sits beside the existing `wasm_bins` generator/validator; reuses the ported library |

### WAT support (extension beyond wasmbin)

wasmbin is binary-only. We add a **WAT (text) ⇄ binary** path so the CLI handles `.wat` too:
parse WAT into the typed model and pretty-print the typed model back to WAT. Owned where feasible
(decision 031); if a third-party WAT grammar is unavoidable it follows the F14 boundary rules
(small, isolated, opt-in). This is the main net-new design work versus a straight port.

## Use cases in this platform

- **F13 discovery**: read the export section type-safely to enumerate `__fwt_` test exports
  (alternative/complement to the walrus scan).
- **F10 / `wasm_bins`**: inject/patch sections during `ewe-wasm build` (e.g. metadata, custom
  sections for execution modes) with `Lazy<T>` minimal-diff re-encoding.
- **CLI**: `inspect` (dump module structure), `edit` (add/remove/patch sections, rename exports),
  `convert` (wasm ⇄ wat), `validate`.
- Anywhere we currently reach for walrus but want type-safe, minimal-diff edits.

---

## Approach

1. **Explore** the wasmbin source; map its modules to a `foundation_codegen::wasm` layout.
2. **Port the derive macros** into `foundation_macros` first (the model depends on them).
3. **Port the core model** module-by-module, with attribution headers, compiling + round-trip
   testing each (parse→serialize identity on real `.wasm` fixtures — reuse the testbed fixtures).
4. **Add the WAT layer** (binary ⇄ text).
5. **Build the CLI** in `foundation_codegentools` (inspect/edit/convert/validate).
6. **Wire NOTICE + README + per-file credit**; record upstream version.

## Future enhancement — reference auto-cleanup (walrus-style, deferred)

wasmbin's faithful 1:1 model means deleting an entity (a function, type, global, …) does **not**
fix up the now-dangling references — that's the one ergonomic edge walrus has (its
`tombstone_arena` + `passes::used`/`gc`). Planned enhancement to our port (deferred, recorded
here so the intent isn't lost):

- When the caller removes an entity, **cache the removed reference/index** (a deletion set /
  tombstones) instead of mutating indices immediately.
- Before serializing, run a **cleanup pass**: compute the live set, drop dead entities, and
  **relocate/renumber references** so the emitted module is consistent — then `Lazy<T>` re-encodes
  minimally.
- This cherry-picks walrus's most valuable capability onto our owned, type-safe model **without**
  porting all of walrus (see F16, deferred). Design reference: walrus `tombstone_arena.rs`,
  `passes/used.rs`, `passes/gc.rs`.

This keeps additive/local edits zero-cost (no pass needed) while making deletions safe on demand.
