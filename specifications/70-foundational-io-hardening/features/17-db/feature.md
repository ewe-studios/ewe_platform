# Feature 17: `foundation_db`

_Written in ASD-STE100 Simplified Technical English (STE). Code and identifiers stay as they
are._

**Abbreviations in this file.** Structured Query Language (SQL); Representational State Transfer
(REST); JavaScript Object Notation (JSON); key-value store (KV); Durable Object (DO); continuous
integration (CI); pull request (PR); AeroSpace and Defence Industries Association of Europe
(ASD), the owner of the STE standard ASD-STE100.

Use the shared protocol in [`requirements.md`](../../requirements.md) sections 3 and 4. One
commit per entry. This feature is large: split it into two PRs if it passes about 1500 changed
lines (E1–E6, then E7–E12), and say so.

## T0. Check that every entry is still open (table in the PR body)

## E1. `StateStore::set` ignores its `resource_id`

- **Where:** `src/core/state/*.rs`, `src/native/{libsql_store,d1_kvstore,r2_blobstore}.rs`: every
  backend keys the write by `state.id`.
- **Fix:** key by `resource_id`, and set `state.id` from it in one shared place (or drop the
  parameter everywhere; choose, say why, keep `NamespacedStore` correct).
- **Test (contract, every backend):** `set_uses_resource_id` — `set("a", &state_with_id_b)` then
  `get("a")` returns it and `get("b")` returns nothing.

## E2. `R2Store` parses R2 REST JSON by hand

- **Problem:** generated Cloudflare types live in `foundation_deployment_cloudflare`, which depends
  on `foundation_db` (rule 5 breach).
- **Fix:** move the generated R2 (and D1, if used) types into a small crate both can depend on
  (for example `foundation_cloudflare_types`, generated by the same generator command); use them
  in `R2Store`. Add the object-listing endpoint to `worker-stub.js` so listing is tested against
  the wrangler stub too.
- **Tests:** existing R2 tests pass on the typed code; `r2_listing_against_worker_stub` (behind
  `CF_INTEGRATION_TEST=1`, like the other wrangler tests).

## E3. R2 state listings hold every matching id before streaming

- **Fix:** a cursor-driven stream (R2 returns keys in order; stream page by page; no sort).
- **Test:** `r2_state_listing_streams_pages` (the mock returns 3 pages; assert the first item is
  yielded before page 2 is requested).

## E4. `BlobStore` moves whole objects; no range, conditional put or ordered listing

- **Where:** `src/core/storage_provider.rs`: `get_blob` returns `Vec<u8>`, `put_blob` takes
  `&[u8]` (rule 4).
- **Fix:** streamed get (a body stream) and streamed put (a body stream with a length when
  known); `get_blob_range(key, range)`; conditional put (`if_none_match: *`, `if_match: etag`)
  returning a `PreconditionFailed` error; `list_after(prefix, start_after, limit)` as an ordered
  stream. Implement on R2 (REST and wasm binding), file and memory stores. Keep the whole-object
  helpers as thin wrappers for small objects only, documented as such.
- **Tests (contract, every backend):** `blob_get_range`, `blob_put_if_none_match_rejects_existing`,
  `blob_put_if_match_rejects_stale_etag`, `blob_list_after_is_ordered`,
  `blob_put_streams_without_buffering` (counting body source).

## E5. `QueryStore` batch takes one raw SQL string with no parameters

- **Fix:** `execute_batch_statements(&[(sql, params)])`: D1 `batch()` of prepared statements; one
  transaction on libsql and Turso. All or nothing.
- **Tests:** `batch_statements_apply_atomically` (the third statement fails; assert none of the
  three applied) per backend that supports it.

## E6. D1 state `init` multi-statement path is only tested by wrangler tests

- **Fix:** a mock-D1 test for `init` (the `/query` body has every statement with its `;`), plus the
  existing wrangler test.

## E7. Auth tables mix timestamp units

- **Fix:** one unit per column (choose milliseconds or seconds; document in the migrations); a
  migration that converts existing rows; `AsyncStorageCleanup` follows the column's unit; the IdP
  server writes the same unit.
- **Test:** `cleanup_deletes_expired_rows_by_documented_unit` (rows just before and just after
  expiry).

## E8. `KVWasmStorage`'s rate limiter is not atomic

- **Fix:** on Workers, use a Durable Object (or D1 with a single `UPDATE … RETURNING`) for rate
  limits; keep KV only as an explicitly best-effort option with a doc warning.
- **Test:** `rate_limit_counts_concurrent_hits` against the D1 path (a mock that serialises like
  D1): 50 concurrent hits, limit 10, exactly 10 allowed.

## E9. Old-shape `rate_limits` tables

- **Fix:** a migration that detects the old shape (`key PRIMARY KEY, count, window_start`) and
  rebuilds the table (rows are disposable).
- **Test:** `old_rate_limit_table_is_rebuilt` (create the old shape, run migrations, use the store).

## E10. Wasm stores keep a second inherent `*_async` API

- **Where:** `D1WasmStorage`, `KVWasmStorage`, `R2WasmStorage` (`src/wasm/wasm_storage/*.rs`).
- **Fix:** make the inherent methods private helpers; route every caller (trait impls,
  `StorageProvider`, `WasmCredentialStore`, `foundation_auth`'s `CredentialStore for
  D1WasmStorage`, `examples/cf-login-app`) through the traits; `list_keys` returns a stream
  (`collect_all` where a `Vec` is needed).
- **Verify:** `rg -n 'pub (async )?fn \w+_async' backends/foundation_db/src/wasm` is empty; wasm
  build of `foundation_db`, `foundation_auth` and `examples/cf-login-app` passes.

## E11. No CI job builds the example workspaces

- **Fix:** an examples job: wasm32 build of each `examples/cf-*`, native build of
  `apps/answerme-agent`. Add it to `ci/packages.toml` / the CI workflow the way other jobs are
  added.
- **Verify:** `python3 scripts/ci/ci.py plan` lists it; it passes in CI.

## E12. Dead-code warnings in `core/rate_limit.rs` in some feature sets

- **Fix:** gate `CREATE_TABLE_SQL`, `RECORD_SQL`, `SELECT_SQL`, `sql_check`, `sql_record`,
  `sql_reset` on the features that use them.
- **Verify:** `cargo check -p foundation_connectrpc --tests 2>&1 | rg 'foundation_db.*never used'` is empty.
